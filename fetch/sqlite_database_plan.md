# 课程规划 SQLite 数据库设计计划

## 结论与范围

拟新建 `fetch/course_planner.sqlite3`，只设两张业务表：`course_offerings` 记录各学期全校开课，`timetable` 记录个人各学期课表。本文为待审阅设计，尚未创建数据库或执行入库，不使用旧项目代码、数据库或既有表结构。

两张表都以“学期内的一门具体教学班”为记录单位。同一门课每周上两次、跨多个大节，仍是一条课程记录，具体上课安排放在该记录的 `meetings_json` 中。这样不会因网页重复展示跨大节课程而重复计算课程数或学分。

这是单人平台，暂不增加用户表、学期表、课程基础表、教师表或导入日志表。来源信息直接保存在两张表中。

## 通用字段约定

`semester` 使用 `2024-2025-1` 格式；课程编号、课序号均使用 TEXT，避免丢失前导零。数值缺失记为 NULL，不擅自填 0；普通文本缺失统一为 NULL。JSON 字段使用 SQLite TEXT 存储有效 JSON。

原始课程名称、性质和属性分别保留，不用“必修／选修”的推断值覆盖源数据。“课程性质”和“课程属性”在源文件中可能不同，应作为两个独立字段。

`created_at`、`updated_at` 统一使用 UTC ISO 8601 时间，由导入程序赋值。下表中的“必填”表示 NOT NULL；带默认值的必填字段可由数据库或导入程序自动提供。

## 表一：course_offerings（全校各学期开课）

一行代表某学期的一门教学班。对于补退选清单里确有开课记录但缺少课序号的课程，允许 `class_no` 为空，保留为待确认记录，不伪造编号。

| 字段 | SQLite 类型 | 必填／默认 | 含义与来源 |
| --- | --- | --- | --- |
| id | INTEGER | 必填，主键 | 内部编号，INTEGER PRIMARY KEY，不使用 AUTOINCREMENT |
| semester | TEXT | 必填 | 学期，从文件名提取并核对 |
| course_code | TEXT | 必填 | 课程编号；兼容源列“课程号” |
| class_no | TEXT | 可空 | 课序号；主表有值，部分补充清单没有 |
| course_name | TEXT | 必填 | 课程名称；兼容源列“课程名” |
| teachers | TEXT | 可空 | 上课教师，保留多人及原始顺序 |
| class_names | TEXT | 可空 | 合班名称，不与“分组名称”混用 |
| campus | TEXT | 可空 | 上课校区 |
| department | TEXT | 可空 | 开课单位 |
| credits | REAL | 可空 | 学分，例如 0.5、2.5；不得从学时倒算 |
| total_hours | REAL | 可空 | 学时，仅解析明确的数值，不能解析时保留原始行 |
| course_category | TEXT | 可空 | 课程类别，例如通识教育课程，主要由参考表补充 |
| course_nature | TEXT | 可空 | 源文件明确给出的课程性质 |
| course_attribute | TEXT | 可空 | 课程属性，例如必修、选修、通选 |
| group_name | TEXT | 可空 | 分组名称 |
| selection_restrictions | TEXT | 可空 | 选课限制说明 |
| gender_requirement | TEXT | 可空 | 性别要求，保留“全部”等原始值 |
| selection_open | TEXT | 可空 | 选课开放状态，保留源文字 |
| weeks_text | TEXT | 可空 | 上课周次原文；补充表仅有组合时间时不编造此字段 |
| time_text | TEXT | 可空 | 上课时间原文，可能包含周次、星期和节次 |
| location_text | TEXT | 可空 | 上课地点原文；仅部分主表提供，不推测缺失地点 |
| meetings_json | TEXT | 必填，默认 `[]` | 解析后的多个上课安排，格式见后文 |
| schedule_status | TEXT | 必填，默认 `unparsed` | `parsed`／`partial`／`unparsed`／`not_provided`，表示时间解析情况 |
| learning_platform | TEXT | 可空 | 学习平台，例如智慧树、楚课联盟 |
| modules_json | TEXT | 必填，默认 `{}` | 所属模块按培养方案版本保存，允许同版本多个模块 |
| remarks | TEXT | 可空 | 备注；多备注列按“备注1：…；备注2：…”保留标签 |
| identity_status | TEXT | 必填 | `confirmed`：学期、课程编号、课序号明确；`provisional`：缺少课序号或身份待确认 |
| sources_json | TEXT | 必填 | 非空来源数组，含原始行和定位信息，格式见后文 |
| created_at | TEXT | 必填 | 首次入库时间 |
| updated_at | TEXT | 必填 | 最近一次实际更新该记录的时间 |

共 30 个字段。`confirmed` 只表示教学班身份明确，不表示已向教务系统实时核验其仍然开课。

### 约束与索引

主键为 `id`。对 `class_no IS NOT NULL` 的记录建立 `(semester, course_code, class_no)` 部分唯一索引。针对 `semester, course_name` 建立普通索引，用于学期内查课。检查 `credits`、`total_hours` 非负，校验状态枚举及 JSON 的有效性。

缺少课序号时不能依靠课程名称强制去重；同名课程可能由不同老师、在不同时间开设。此类记录通过来源文件哈希、工作表和行号识别同一批数据的重复导入；内容完全相同的重复行可合并，但所有来源位置必须保留。疑似同一教学班且证据不足时保留为待确认，不建立虚假唯一关系。

## 表二：timetable（个人各学期课表）

一行代表个人课表中的一门教学班，包含无明确上课安排的已选课程。个人课程名称、老师和地点独立保留，不在读取时完全依赖全校开课表，避免全校清单缺项或变更影响个人历史记录。

| 字段 | SQLite 类型 | 必填／默认 | 含义与来源 |
| --- | --- | --- | --- |
| id | INTEGER | 必填，主键 | 内部编号，INTEGER PRIMARY KEY |
| semester | TEXT | 必填 | 学期，优先采用网页实际选中学期 |
| offering_id | INTEGER | 可空，外键 | 对应 `course_offerings.id`；匹配不到保留 NULL |
| course_code | TEXT | 必填 | 个人课表明细中的课程编号 |
| class_no | TEXT | 可空 | 课序号 |
| course_name | TEXT | 必填 | 个人课表中的课程名称 |
| teachers | TEXT | 可空 | 授课教师；明细中的姓名原值 |
| class_names | TEXT | 可空 | 上课班级；异常的班级标识字符串照录，不当作正常名称改写 |
| course_nature | TEXT | 可空 | 个人课表中的课程性质 |
| course_attribute | TEXT | 可空 | 个人课表中的课程属性 |
| has_schedule | INTEGER | 必填 | 1：有课表课程；0：无课表课程，CHECK 限制为 0 或 1 |
| time_text | TEXT | 可空 | 上课时间原文，包含周次、星期、节次 |
| location_text | TEXT | 可空 | 上课地点原文，可含多处地点 |
| meetings_json | TEXT | 必填，默认 `[]` | 解析后的上课安排，按实际小节记录，不按网页大节复制课程 |
| schedule_status | TEXT | 必填，默认 `unparsed` | `parsed`／`partial`／`unparsed`／`not_provided` |
| notice_number | TEXT | 可空 | 网页隐藏详情中的通知单编号，用于辅助核对教学班身份 |
| online_group | TEXT | 可空 | 网课群号，来自 Excel 或网页详情 |
| online_url | TEXT | 可空 | 网课链接网址，完整保留 |
| qr_reference | TEXT | 可空 | 源数据明确提供的二维码链接或图片引用；没有则 NULL |
| remarks | TEXT | 可空 | 可明确归属于本课程的备注；页面整表备注留在来源中 |
| sources_json | TEXT | 必填 | 原始课程行、网页单元格详情及 Excel 来源的非空数组 |
| created_at | TEXT | 必填 | 首次入库时间 |
| updated_at | TEXT | 必填 | 最近一次实际更新该记录的时间 |

共 23 个字段。个人课表本身没有提供学分、学时，不重复存放从全校开课表推导的数值；需要时通过 `offering_id` 查询，未匹配则明确显示未知。

### 约束与关联

对 `class_no IS NOT NULL` 的记录建立 `(semester, course_code, class_no)` 部分唯一索引，并为 `offering_id` 建普通索引。外键使用 `ON DELETE SET NULL`，每次连接显式启用 `PRAGMA foreign_keys = ON`，避免删除全校开课记录时连带删除个人课表。

匹配优先使用“学期＋课程编号＋课序号”，必须唯一命中且不存在明显教师、课程身份冲突才能关联。缺少课序号、编号相同但内容冲突、无法唯一命中时，`offering_id` 保持 NULL，并在导入报告列出原因。不能单凭课程名称关联。

外键只能保证目标行存在；导入程序还要检查关联两侧的学期、课程编号和课序号一致。初版不增加维护这些条件的触发器。

## JSON 字段的完整约定

### meetings_json

使用对象数组，每个对象表示同一周次规则下的一次每周上课安排。以下仅为格式示例：

```json
[
  {
    "weekday": 1,
    "weeks": [1, 2, 3, 4, 5, 6, 7, 8],
    "periods": [6, 7, 8, 9],
    "location": "文泉南银行与证券及金融工程实验室104",
    "raw_text": "1-8周 星期一 06070809节",
    "source_entry": 0
  }
]
```

每个对象只有上述六个字段：`weekday` 为 1—7 的整数或 NULL；`weeks` 为实际教学周整数数组，不能确定时为 NULL；`periods` 为实际小节整数数组，不能确定时为 NULL；`location` 为地点文本或 NULL；`raw_text` 为本次安排的原文；`source_entry` 为 `sources_json` 中的来源下标。

单双周先解析为实际周序号数组，不丢失原文。星期天与星期日统一为 7。组合字段只有在周次、时间和地点的数量及对应关系明确时才按位置配对；不明确时保留原文并标记 `partial`，不把多个时间、地点做笛卡尔积。没有明确课表时数组为 `[]`，状态为 `not_provided`，而不是判定该课程已结束。

本轮不存统一的“第几大节→钟点”映射：不同学期页面节次模式可能不同。课程使用实际小节表达；页面行标题和钟点留在原始 JSON／HTML 中。将来显示日历时间时按对应学期的节次模式读取，不能套用最新学期的钟点。

### modules_json

对象的键是版本号，值是模块名称数组，例如 `{"2022": ["家国情怀"], "2024": ["读懂中国与“五史”教育"]}`。源列只有“所属模块”而没有注明版本时使用 `unspecified`，不擅自归入 2024 版。没有模块信息为 `{}`。

### sources_json

非空对象数组。每个来源对象具有以下全部字段；不适用的字段取 NULL：

| 字段 | JSON 类型 | 含义 |
| --- | --- | --- |
| kind | string | `main`、`supplement`、`reference`、`personal_excel`、`personal_web` |
| file | string | 相对项目根目录的来源路径，不保存 Cookie |
| sha256 | string | 来源文件 SHA-256，定位具体版本 |
| sheet | string/null | Excel 工作表名 |
| row | integer/null | Excel 原始行号，从 1 开始 |
| json_pointer | string/null | JSON 中的原始记录位置，例如 `/scheduled_courses/0` |
| raw | object | 原始列名和单元格值；网页课程同时保留匹配到的完整单元格详情 |

重复来源合并为多个来源对象，原始冲突值也保留在各自 `raw` 中。页面级学期、节次标题及整表备注通过来源 JSON 文件保留，不把整页内容重复写进每条课程。

## 导入与冲突处理计划

1. **只读盘点。** 识别文件类型、学期和表头，跳过标题、空行和空工作表。兼容“课程号／课程编号”“课程名／课程名称”“上课教师／授课教师”等字段别名。记录原始行号，不修改源 Excel。
2. **先导入主表，再处理补充。** 五份主表提供教学班身份和主要开课字段。参考表仅补充空缺的课程类别与模块；同学期、同课程编号出现不同学分、属性等值时保留冲突，不把某个参考行覆盖到所有教学班。補退选清单不依据文件名自动执行删除，也不把“新增”说明当作选课成功状态。
3. **导入个人课表并关联。** 网页 JSON 为主要快照，历史 Excel 作核对和补充；来源之间存在差异时在报告中保留，不静默替换。无课表课程同样入库。读取明细记录生成课程行，网页大节单元格只用于补充详情，避免跨大节重复记录。
4. **解析排课与检查匹配。** 保留全部原文，解析周次、星期、小节和教室，检查数组对应关系。进行教学班键匹配，无法确定则保留 NULL 外键和待处理原因。
5. **事务写入与报告。** 正式执行时按学期在事务中导入，按业务键和来源标识保证重复导入不新增副本；不通过清空表重建完成更新，也不因新文件缺少旧行而自动删除。每学期报告源行数、新增数、合并数、冲突数、解析异常和未匹配个人课程，报告文件也放在 `fetch/`。

补充表中已观察到完全重复的课程行，正式入库必须去重并保留多来源定位。参考表中未能匹配任何实际开课记录的条目写入导入报告，不丢弃证据，也不计入“已确认开课”数量。

## 验收标准与执行边界

主表 16,546 条记录均应有对应记录及来源定位，补充后的增量必须可解释；个人课表当前基数 63 条应逐学期核对。课程编号、课序号、学分、周次与源值一致，缺失字段和未匹配记录不能被过滤掉。

重复导入相同文件后课程记录数不变；部分唯一约束、外键检查及事务回滚有效；时间解析失败保留原文，并计入异常报告。数据库只存内容和关联，不承担复原 Excel 字体、颜色、合并单元格的职责，原始文件继续保留。
