# 项目总览

## 1. 项目目标

学旅 Study Journey 是一个本地课程规划 Web 应用，目标是把学校培养方案、个人选课计划、课程修读状态、学分进度和学校原始开课数据统一到一个可视化界面中。

项目不是完整教务系统，也不是自动抢课或自动选课工具。它的定位是：

```text
培养方案理解工具 + 个人课程计划工具 + 学校开课数据查询工具
```

## 2. 核心用户场景

当前版本围绕以下场景设计：

| 场景 | 说明 |
|---|---|
| 查看培养方案 | 按通识教育、大类平台、专业教育、素质教育、实践教育查看课程与学分要求 |
| 安排八学期计划 | 将课程放入 1-8 学期，形成个人时间轴 |
| 添加自选课程 | 添加通识选修、跨专业、经法管融通、其他自定义课程 |
| 查看学分进度 | 按培养方案要求统计已修、正在修读、计划修读和待安排课程 |
| 查询原始开课数据 | 查询学校完整选课表、补退选表、课程一览表中的课程 |
| 使用垃圾篓 | 删除课程后可恢复；官方课程和自定义课程删除语义不同 |
| 查看旅迹页 | 用可视化方式展示个人学习路径与学分结构 |

## 3. 核心概念

### 3.1 官方培养方案课程

官方培养方案课程是培养方案中明确要求或明确列出的课程，存放在：

```text
plan_program_courses
```

典型内容包括：

```text
通识教育必修
大类平台必修
大类平台选修候选
专业教育必修
专业教育选修候选
素质教育必修
实践教育必修
```

官方课程的特点是：即使用户在界面上“永久删除”，数据库也不应物理删除课程记录，而是通过 `is_permanently_deleted` 做用户视角隐藏。这样可以保证培养方案始终有最后备份。

### 3.2 用户自选/自定义课程

用户自选课程和自定义课程存放在：

```text
plan_custom_courses
```

当前项目约定：

```text
通识教育-选修
通识教育-跨专业
通识教育中的经法管融通选择
用户自行添加的课程
```

都应放入 `plan_custom_courses`。这些课程不是培养方案中固定列出的“必修主干”，而是用户根据自己的选课行为形成的个人课程集合。

自定义课程可以进入垃圾篓，也可以物理删除，不需要 `is_permanently_deleted`。

### 3.3 学校原始开课数据

学校原始开课数据存放在 `raw_*` 表中：

```text
raw_import_batches
raw_term_course_sections
raw_term_added_courses
raw_course_catalog_previews
```

raw 表只保存学校原始事实，例如课程号、课序号、教师、上课时间、开课单位、补退选信息、课程模块等。raw 表不直接承担用户计划、成绩、删除状态。

### 3.4 我的计划与官方计划

当前前端时间轴同时呈现两类视角：

| 视角 | 含义 |
|---|---|
| 官方计划 | 从培养方案角度查看课程所属类别和官方安排 |
| 我的计划 | 从用户角度查看计划学期、成绩、修读状态和自选课程 |

两者会共享部分课程信息，但写入语义不同。官方计划不能替代用户计划，用户计划也不应覆盖学校原始数据。

## 6. 非目标

项目当前不做以下事情：

1. 不替代学校教务系统。
2. 不负责真实选课、退课或抢课。
3. 不保证 raw 表课程一定可选，只保留学校文件中的历史事实。
4. 不把 raw 表直接作为个人培养方案。
5. 不把通识选修直接写入官方培养方案主表。
6. 不引入复杂后端框架或大型 ORM。

## 7. 边界判断原则

判断一条课程数据应放在哪张表，可以按下面规则：

| 问题 | 结论 |
|---|---|
| 这门课是否是培养方案固定列出的主干课？ | 是：`plan_program_courses` |
| 这门课是否是用户自己选择的通识选修/跨专业课？ | 是：`plan_custom_courses` |
| 这门课是否只是学校某学期开课表中的一条记录？ | 是：`raw_*` |
| 这门课是否带有教师、时间、地点、课序号等教学班信息？ | 通常属于 `raw_term_course_sections` |
| 这门课是否来自补退选/新增课程表？ | 属于 `raw_term_added_courses` |
| 这门课是否来自通识/经法管融通/素质课程一览表？ | 属于 `raw_course_catalog_previews` |
