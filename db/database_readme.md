# course_planner.sqlite 数据库说明文档

本文档用于说明当前课程规划数据库的结构、字段含义、已完成进度、未处理数据与特殊规则。数据库目前采用 SQLite，本地数据库文件存放位置为：

```text
 db/course_planner.sqlite
```

建表脚本统一放在：

```text
 migrations/
```

插入数据脚本统一放在：

```text
 seeds/
```

当前数据库设计原则是：课程基础信息只保存在 `courses` 表中；通识教育、大类平台、专业方向、素质教育、实践教育等表只记录课程归属关系，不重复保存课程名称、学分、学时等信息。

---

## 二、各表字段说明

### 1. `courses`：课程基础信息表

该表是整个数据库的核心表。其他课程归属表、学期修读记录表都通过 `course_code` 引用它。

| 字段名 | 类型 | 约束 | 中文含义 | 说明 |
|---|---|---|---|---|
| `course_code` | `TEXT` | 主键 | 课程号 | 学校培养方案或教务系统中的课程编号，例如 `B2490050`。当前使用课程号作为主键。 |
| `course_name` | `TEXT` | 非空 | 课程名称 | 课程正式名称，例如“思想道德与法治”。 |
| `credits` | `REAL` | 非空，`>= 0` | 学分 | 允许小数学分，例如 `2.5`、`0.5`。 |
| `lecture_hours` | `INTEGER` | 非空，默认 `0`，`>= 0` | 课堂学时 | 理论讲授或课堂教学学时。Excel 为空时按 `0` 处理。 |
| `experiment_hours` | `INTEGER` | 非空，默认 `0`，`>= 0` | 实验学时 | 实验、实践、上机等学时。Excel 为空时按 `0` 处理。 |
| `extra_hours` | `INTEGER` | 非空，默认 `0`，`>= 0` | 课外学时 | 课外、自学、拓展等学时。Excel 为空时按 `0` 处理。 |
| `prerequisite_course_code` | `TEXT` | 可空，外键 | 先修课程号 | 如果课程有先修条件，则保存先修课程的课程号；如果没有先修条件，则为 `NULL`。 |

补充说明：

- `course_code` 和 `course_name` 不能是空字符串。
- `prerequisite_course_code` 外键引用 `courses(course_code)`。
- 当前按用户确认，学校每门课只有一个先修条件，因此暂不单独建立多对多先修关系表。
- 已确认的特殊先修关系包括：
  - `B0900490` 高等数学(2) 的先修课程是 `B0900470` 高等数学(1)。
  - `B0901323` 线性代数的先修课程是 `B0900434` 概率论与数理统计(经管)。
  - `B0301940` 计量经济学的先修课程是 `B0900490` 高等数学(2)。
  - `B0300510` 金融计量学(双语) 的先修课程是 `B0301940` 计量经济学。
  - `B2090030` 军训没有先修条件。

## 四、目前存在的情况

### 1. 数据库采用“课程基础信息 + 模块归属表”的结构

课程名称、学分、课堂学时、实验学时、课外学时等内容只保存在 `courses` 表中。其他模块表只通过 `course_code` 引用课程，不重复保存课程本体信息。

这样可以减少数据冗余。例如课程名称如果需要修改，只需要改 `courses` 表，不需要同步修改多张表。

### 2. 已完成课程和未完成课程分开处理

`semester_courses` 只记录已经完成的课程。Excel 中没有完成学期或完成情况的课程不写入该表。

后续学期结束后，如果有新成绩，可以手动逐条插入 `semester_courses`。

### 3. 完成学期和分数不写入课程归属表

完成学期和分数属于个人修读记录，不属于课程本体，也不属于培养方案模块归属，因此只应该写入 `semester_courses`。

### 4. 当前先修关系只支持一个先修课程号

当前 `courses.prerequisite_course_code` 只支持一门课对应一个先修课程。用户已确认目前学校课程每门课只有一个先修条件，所以暂不修改。

### 5. 经法管融通规则已单独进入培养方案要求表

“经法管融通”不是一门具体课程，因此不放入 `courses` 表。其 6 学分要求放入 `program_requirements`。

## 五、发生过的意外情况

### 1. 部分 Excel 记录没有课程号

原始 Excel 中存在有学分或完成情况、但没有课程号的记录。由于当前设计使用 `course_code` 作为主键，这类记录不能直接插入 `courses` 表，也不能作为外键插入其他表。

### 2. “先修条件”原本不是课程号

Excel 中部分先修条件写的是课程名称或简称，例如“高等数学”“计量经济”。但数据库要求保存课程号，因此这些内容需要人工确认后转换为课程号。

已确认并转换的包括：高等数学(2)、线性代数、计量经济学、金融计量学(双语)、军训。

### 3. “军训”的先修条件异常

原始数据中军训的先修条件位置曾出现 `1`。经用户确认，军训没有先修条件，因此最终写为 `NULL`。

### 4. 曾经生成过中文视图

曾生成 `general_education_courses_zh` 视图用于中文显示，但用户明确表示暂时不需要中文视图，之后已手动删除。当前文档按“不保留中文视图”处理。

### 5. “户外运动”最初没有课程号

最初 Excel 中“户外运动”没有课程号，因此没有插入。后来用户查到课程号为 `B1580180`，已经给出单独补充命令。是否已经写入本地数据库，以用户是否执行该命令为准。

### 6. “经法管融通”不是普通课程

“经法管融通”实际上是中南财经政法大学的特殊课程类别或学分要求，不是一门具体课程。因此没有作为 `courses` 记录插入，而是放入 `program_requirements` 作处理。

## 七、需要额外附注的说明

### 1. 外键检查需要在每次 SQLite 连接后开启

SQLite 的外键检查需要执行：

```sql
PRAGMA foreign_keys = ON;
```

脚本中已写入该语句，但以后通过 Python、Node 或其他程序连接数据库时，也要在连接后开启外键检查。

### 2. 建表脚本和插入脚本应分开保存

当前约定：

```text
migrations/xxx_create_xxx.sql   # 建表脚本
seeds/xxx_seed_xxx.sql          # 插入数据脚本
```

这样数据库文件可以随时删除后重新生成，结构和数据来源也更容易追踪。

### 3. 不建议直接在 DB Browser 中修改表结构

DB Browser 或 DBeaver 可以用来查看数据、临时查询、检查结果，但表结构应优先通过 `.sql` 文件维护。

### 4. 目前不处理中文字段名

数据库字段名统一使用英文，例如 `course_code`、`course_name`。中文含义通过文档说明，不再使用中文视图或中文字段名。

### 5. 经法管融通的“不重复计分”尚未做自动判断

用户已确认经法管融通类课程可以作为公选课，也可以作为大类平台选修课，但不能重复计分。

当前数据库只记录了这个类别的学分要求，没有实现自动判定逻辑。后续如果要自动审查学分，需要额外设计“课程计入哪个要求”的记录表。

### 6. 后续新成绩应逐条插入 `semester_courses`

未完成课程暂不记录。后续学期结束后，有成绩的课程再插入，例如：

```sql
INSERT INTO semester_courses (term_number, course_code, score)
VALUES (4, '某课程号', 88);
```

如已存在该课程记录，可使用 `ON CONFLICT(term_number, course_code) DO UPDATE` 更新分数。
